## Goal

A deployable skeleton that every later milestone builds on: Next 16 and Payload 3 running in one app on a MongoDB replica set, the core `lib/` files, the module folder convention, the test runners, CI, a Docker image and a staging deployment. After M1.1 a developer can clone the repo, run `docker compose up -d && npm run dev`, open `/admin`, create the first admin, and see `/api/health` return `200`.

## In scope / out of scope

- **In:** the tasks below.
- **Out:** any design or page (M1.2), the CMS collections (M1.3), media storage (M1.3), e-mail (M1.3).

## Tasks

### T1 · Payload + Next compatibility gate (D-02)
Files: `package.json`, `next.config.ts`, `payload.config.ts`, `app/(payload)/**` (generated), `PROGRESS.md`.

1. Install the Payload packages with `--save-exact`. Read their `peerDependencies` for `next` and `react`.
2. If Next 16.4.3 is in range, keep it. If it is not, pin `next`, `react`, `react-dom` and `eslint-config-next` to the highest versions Payload supports. Record the result as D-02 in `01-CONTEXT.md` §7 and the versions in `02-ARCHITECTURE.md` §1.
3. Add Payload's admin and API route files under `app/(payload)/` exactly as the installed `@payloadcms/next` version documents (copy them from its template or README in `node_modules`; do not invent paths). Wrap `next.config.ts` with `withPayload`.
4. `payload.config.ts`: `db: mongooseAdapter({ url: env.DATABASE_URL, transactionOptions: {} })`, `editor: lexicalEditor()`, `secret`, `typescript.outputFile: 'payload-types.ts'`, `localization` (fr default, en, de, pt, `fallback: true`), `collections: [...modules]` composed from the module files, and `graphQL.disable: true` if the installed version supports it (we do not use GraphQL).
5. Delete the create-next-app scaffold (`app/page.tsx` content, `public/*.svg`, Geist fonts).

Verify: `npm run build` succeeds, `/admin` loads, and creating the first user works.

### T2 · Tooling

Verify: `npm run lint`, `npm run typecheck` and `npm run build` pass.

### T3 · Core library
Files: `lib/env.ts`, `lib/payload.ts`, `lib/tx.ts`, `lib/errors.ts`, `lib/action.ts`, `lib/access.ts`, `lib/money.ts` (+ test), `lib/time.ts`, `lib/audit.ts`, `lib/rate-limit.ts`, `lib/cn.ts`.

- `env.ts`: zod schema, **parsed lazily on first access** so that `next build` works with no env.
- `tx.ts`: `withTx(payload, fn)`. Before writing it, read how the installed Payload version starts, commits and kills a transaction (`initTransaction`, `commitTransaction`, `killTransaction` or `payload.db.beginTransaction`), and how to get the Mongo `ClientSession` for a raw `collection.updateOne(…, { session })`. Expose `{ req, session, model(slug) }`. Document the verified API in a 3-line comment. This is the only file that knows it.
- `action.ts`: `action(schema, { roles }, fn)` and `publicAction(schema, fn)` per `03-CODING-LAWS.md` §4.1. Read the user with `payload.auth({ headers: await headers() })`.
- `access.ts`: `isStaff(...roles)`, `staffOrSelf(field)`, `publicRead`, `published`, `none`.
- `money.ts`: `add`, `mulQty`, `pct(cents, bp)` (half-up), `vatFromGross(gross, bp)`, `netToGross(net, bp)`, `formatMoney(cents, locale)`.
- `rate-limit.ts`: `rateLimit(key, max, windowMs)` using a conditional upsert on `rateLimits` (TTL index on `expiresAt`); it throws `AppError('RATE_LIMITED')`.
- `audit.ts`: `audit(req, action, { collection, id }, before?, after?)`.

### T5 · Health, CI, Docker, staging
Files: `app/api/health/route.ts`, `.github/workflows/ci.yml`, `Dockerfile`, `.dockerignore`, `next.config.ts` (`output: 'standalone'`, `poweredByHeader: false`, `images.remotePatterns` for the S3 public URL).

- `/api/health`: pings Mongo (`db.admin().ping()`) with a 2 s timeout and returns `200 {"ok":true,"mongo":"up"}`, or `503`. It must never be prerendered; check in the Next docs how 16.4 marks a route handler dynamic.

## Acceptance criteria

- **AC-M1.1-01 [R9]** Given a fresh clone, when the README steps are followed, then `/admin` loads, the first admin can be created, and `/api/health` returns `200`.
- **AC-M1.1-02 [V-SEC]** Given no env vars, when `npm run build` runs, then it succeeds.
- **AC-M1.1-03 [R9]** Given a function that writes two documents in `withTx` and throws after the first, when it runs, then neither document exists.
- **AC-M1.1-04 [V-SEC]** Given `rateLimit('k', 3, 60000)`, when it is called 4 times in the window, then the 4th throws `RATE_LIMITED`.
- **AC-M1.1-05** `npm run check` and `npm run test:int` pass in CI on the first push.
