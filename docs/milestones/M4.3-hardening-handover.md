## Tasks

### T1 · Security review
Files: `next.config.ts` (headers), `proxy.ts`, `lib/rate-limit.ts` callers, `docs/handover/security-review.md`.

- Headers: `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (camera allowed only on `/staff`, for scanning), `frame-ancestors 'none'`, and a CSP built per the Next 16 CSP guide (nonce-based if the guide recommends it for this version), allowing wallee, Google (reviews), Turnstile and S3 media only.
- Turnstile on the public forms (contact, catering, sign-up, event booking, checkout as a guest), verified server-side in `publicAction` through one `verifyTurnstile(token, ip)` helper. Honeypots stay.
- Rate limits reviewed: logins (customer and staff), password reset, every public action, the webhook (generous), and attendance.
- Access review: a table in `security-review.md` listing every collection × role × operation, generated by a script that reads the Payload config (`scripts/access-matrix.ts`) so it cannot drift. It is checked against `04-DATA-MODEL.md`, and every discrepancy is fixed.
- Dependency audit: `npm audit --omit=dev`, with every high or critical finding fixed or justified in the document.
- Secrets: `git log -p | grep` for keys returns nothing; `.env.example` has no real values.

### T2 · Backups and restore
Files: `scripts/backup.sh`, `scripts/restore.sh`, `docs/handover/backups.md`.

- `backup.sh`: `mongodump --uri "$DATABASE_URL" --gzip --archive` to a dated file, uploaded to a separate S3 bucket or prefix, with retention (7 daily, 4 weekly, 6 monthly). Media is already on S3; the doc explains how to enable bucket versioning.
- `restore.sh`: restore into a **new** database name, then run `rebuild-stock --check` and a document-number continuity check (`scripts/check-numbering.ts`: no gaps per series and year).
- **The restore test runs for real** on staging data, and the result (duration, checks passed) is recorded in PROGRESS (Q§05 M6 "backup script and restore test").
- Health-check job: `/api/health` is monitored by the host or an uptime service (documented); there is a cron `health-digest` only if APPLUX wants an e-mail.

### T3 · Performance pass
- Lighthouse (mobile) on home, shop, product, snack and checkout on staging: target Performance ≥ 85, Accessibility ≥ 95, SEO 100. Record the scores and fix the top issues (image `sizes`, the font display, client bundle size; check that heavy modules such as `@zxing/browser` and `@react-pdf/renderer` are loaded only where used).
- Real phones (iOS Safari, Android Chrome): the staff flows feel instant on a 4G connection, and every Mongo query used in lists is checked with `explain()` against the indexes in `04-DATA-MODEL.md` (`scripts/check-indexes.ts` prints any collection scan).

### T4 · Placeholder and content sweep (V-DES)
- No lorem ipsum, "TODO", draft legal page, missing ALT text, missing translation (the key-parity test from M1.2), or a button that leads nowhere. Every prototype route is ported. A script `scripts/check-content.ts` lists draft legal pages, media without ALT, and published products without an image or translation in any locale.

- **AC-M4.3-01 [V-SEC]** Security headers and the CSP are present on public, staff and admin pages; Turnstile blocks a scripted form submission; the access matrix matches `04-DATA-MODEL.md` with no discrepancy.
- **AC-M4.3-02 [V-SEC]** A backup taken on staging restores into a new database with stock and numbering checks passing. The duration and results are recorded.
- **AC-M4.3-03 [V-SEO]** Lighthouse mobile scores meet the T3 targets on the 5 pages, or each gap is documented with its cause.
- **AC-M4.3-04 [V-DES]** `scripts/check-content.ts` reports nothing, and the key-parity test passes.
- **AC-M4.3-05 [R3] [R2]** With CashMag disconnected, every channel keeps selling and `rebuild-stock --check` reports no difference.
- **AC-M4.3-06 [V-SEC]** A fresh environment deployed by following `docs/handover/deployment.md` only starts, serves the site and admin, and passes `/api/health`.
- **AC-M4.3-07** Every acceptance criterion from M1.1 to M4.2 is recorded as passing on staging in `PROGRESS.md`.
