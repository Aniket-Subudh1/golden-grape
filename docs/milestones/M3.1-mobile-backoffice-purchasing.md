## Goal

Staff run the shop from a phone: scan a barcode (camera or Bluetooth scanner), see and adjust stock, count, receive a purchase order, sell to a customer on a visit, and handle today's orders. Purchasing records suppliers, supplier prices and purchase orders, with partial receipts and a reorder list. Low stock is e-mailed daily. Acceptance: **a full receive-and-sell cycle can be done from a smartphone only.**

## In scope / out of scope

- **In:** the tasks below.
- **Out:** B2B customer prices in the mobile sale (M3.2: the sale calls `quote`, so it picks them up automatically once M3.2 lands), wallee links (M4.1), attendance (M3.3), offline mode (out of scope).

## Tasks

### T1 · Staff shell
Files: `app/(staff)/staff/layout.tsx`, `app/(staff)/staff/login/page.tsx`, `app/(staff)/staff/page.tsx`, `components/staff/{top-bar,tab-bar,tile}.tsx`, `proxy.ts` (add `/staff` guard).

- `proxy.ts` redirects to `/staff/login` when the Payload staff cookie is missing (an optimistic check only). `layout.tsx` performs the real check with `payload.auth()`: the user must be active and have a staff role, otherwise it redirects.
- Login uses the staff `users` collection (Payload login operation via an action), with a rate limit.
- The UI language follows `users.locale`, using the same dictionaries under the `staff.*` namespace.
- Home tiles (`05-UI-SYSTEM.md` §5): today's orders by status, open reservations, a low-stock count, and POs expected today. Each tile links to its screen.
- The tab bar is filtered by role and by `isModuleOn`.
- Add a web app manifest (name, icons from the logo, `display: standalone`, `start_url: /staff`) so staff can add it to their home screen (Q§06). There is no service worker and no offline mode.

### T2 · `ScanField`
Files: `components/staff/scan-field.tsx`, `modules/catalogue/actions.ts` (`lookupBarcode`).

- One component: an autofocused text input (a hardware scanner types into it and Enter submits), plus a camera button that opens a bottom `Sheet` with a `BrowserMultiFormatReader` on the rear camera, decoding EAN-13, EAN-8, UPC-A and Code 128. On a decode it vibrates (`navigator.vibrate`), closes, and submits. The camera stream is stopped when the sheet closes; verify there is no leaked track.
- `lookupBarcode(code)` → `findByBarcode` → `{ variant, unit, factor, name, image, onHand, priceCents }`, or `NOT_FOUND` with a "create product" link to the admin for managers.
- Every staff screen reuses this component. There is no second scanner implementation.

### T3 · Stock screens
Files: `app/(staff)/staff/scan/page.tsx`, `stock/[variant]/page.tsx`, `count/page.tsx`, `count/[id]/page.tsx`.

- Scan → product card (image, name, on hand in base units with an "= N boxes of 6" hint, price, packaging units) → actions Adjust, Count and Sell, filtered by role.
- `stock/[variant]`: the last 50 movements (the same service as the admin list) + an adjust form (reuses `adjustStock` from M2.1).
- Count: open or create a count. Each scan adds 1 base unit or 1 package × factor (the scanned barcode decides which), and the quantity can be edited. "Post count" calls `postCount` from M2.1. The count lines are saved server-side on every change (debounced), so a lost connection loses at most one entry.

### T4 · Purchasing
Files: `modules/purchasing/{collections,service,actions}.ts`, `app/(staff)/staff/receive/page.tsx`, `receive/[po]/page.tsx`.

- `suppliers`, `supplierProducts` and `purchaseOrders` as in `04-DATA-MODEL.md` §5. POs are created and edited in the Payload admin (law 1). The PO number comes from `nextNumber('purchase')` when the status leaves `draft`.
- Supplier columns from the catalogue import (M2.1 T6 staging JSON) are loaded into `supplierProducts` by `scripts/import-catalogue.ts --suppliers`.
- `receive(poId, lines: { variant, unit?, unitQty, reason? }[])` runs one transaction: it posts `receipt` movements (base units), increments `receivedUnitQty`, sets the status (`partly_received` or `received`), and updates `variants.costCents` from the PO line cost ÷ factor (rounded). Over-receipt requires a reason. A line not on the PO requires a manager role and is added to the PO.
- Receive screen: pick an open PO (sorted by expected date) → scan items, each scan incrementing the matching line (unit-aware), with remaining quantities shown → confirm → summary.
- **Reorder list** (admin custom view, and `/staff` tile): variants with `lowStock` + their cheapest `supplierProducts` + a suggested quantity of `threshold × 2 − onHand`, rounded up to the supplier unit. It is shown as a suggestion, not an automatic order (Q§13). A manager can "Create draft PO for supplier X" from the selected rows.

### T5 · Mobile sale and staff orders
Files: `app/(staff)/staff/sale/page.tsx`, `orders/page.tsx`, `customers/page.tsx`, `customers/[id]/page.tsx`, `modules/sales/actions.ts` (`placeStaffOrder`).

- Sale flow: pick or create a customer (search by name, company, phone, email; quick create with name and phone, plus company and VAT for business) → scan or search lines (packaging-aware) → live `quote` with `channel: 'mobile'` and the customer → choose payment: "Paid on site" (`manual/onsite` → `confirmed` + `payment.status: paid`) or "Invoice later" (`manual/invoice` → `confirmed`, unpaid; the invoice is issued in M3.2). It reuses `placeOrder`'s service with `channel: 'mobile'`, `mode: 'instore'` or `'b2b'`, and `staff: user`, so there is no second order path.
- Orders screen: today and upcoming orders and reservations, with status buttons calling `transition` (the same staff action as the admin buttons).
- Customers screen: search, view (contact, addresses, the last 10 orders), create and edit basics.

### T6 · Low-stock alerts and cron
Files: `app/api/cron/[job]/route.ts`, `modules/inventory/jobs.ts`, `modules/notifications/templates/low-stock.tsx`.

- The cron route checks `Authorization: Bearer CRON_SECRET`. Job `low-stock-digest` runs daily at 07:00 Luxembourg time from the host's cron: one e-mail to `alerts.lowStockEmail` listing every low-stock variant with on hand, threshold and supplier. It is not sent if the list is empty.
- The dashboard tile (T1) and the admin low-stock list (M2.1) cover the "dashboard alerts" part of R1.
- Document the cron line in `README.md` (handover in M4.3).

### T7 · Tests
- Integration (`modules/purchasing/receive.int.test.ts`): a PO of 2 × box12 at cost 120.00 → +24 base units, `received`, `variants.costCents = 1000`; partial receipt of 1 → `partly_received`, +12; receiving more than remains without a reason → rejected.
- Integration: `placeStaffOrder` with `channel: 'mobile'` writes movements with `channel: 'mobile'` and `user = staff`.
- E2E: `tests/e2e/staff-mobile.spec.ts` (Pixel 7 viewport; the barcode is typed into `ScanField` as a hardware scanner would; the camera is not automated).

## Acceptance criteria

- **AC-M3.1-01 [R4] [R6]** Given a phone only, when a staff user receives a PO by scanning and then sells two of the received items to a customer, then stock rises by the receipt and falls by the sale, and both appear in the ledger with user and channel.
- **AC-M3.1-02 [R1]** Given a product with an EAN, when it is scanned with the phone camera in iOS Safari and Android Chrome, then the product card opens within ~1 s of a steady frame.
- **AC-M3.1-03 [R1]** Given a Bluetooth/USB scanner paired as a keyboard, when a barcode is scanned into any staff screen, then it behaves exactly like the camera scan.
- **AC-M3.1-04 [R12] [R6]** Given a PO line of 2 × box12, then receiving it adds 24 bottles, and a PO can be partly received and completed later.
- **AC-M3.1-05 [R6]** Given low-stock variants with suppliers, then the reorder list shows suggested quantities in supplier units, and a draft PO can be created from it.
- **AC-M3.1-06 [R1] [V-NOTIF]** Given variants below threshold at 07:00, then one low-stock e-mail lists them. Given none, then no e-mail is sent.
- **AC-M3.1-07 [R4]** Given a user with only the `stock` role, then the sale and customer screens are not in the tab bar and their URLs return 404.
