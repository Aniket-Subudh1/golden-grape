## Goal

Every public content page is editable in the admin in four languages. Business settings (info, hours, VAT, numbering, module switches) live in one screen. Staff log in with the Admin, Manager, Sales, Stock and Attendance roles. The contact and catering forms send real requests and e-mails. P1's acceptance (Q§05 M1) passes: all routes work in four languages without mixing, an admin edit of hours or a text updates the site, and the header is readable everywhere.

## In scope / out of scope

- **In:** the tasks below.
- **Out:** event *booking* (M2.3: the Reserve button stays hidden until then); shop and snack (M2.2); customer accounts (M2.2).

## Tasks

### T1 · Staff users and roles
Files: `modules/settings/collections.ts`, `lib/access.ts`.

- Complete `users` per `04-DATA-MODEL.md` §1: field-level access on `roles` (admin only); a `beforeChange` hook that stops an admin removing their own admin role; a `beforeLogin` hook that rejects `active: false`; and `admin.useAsTitle: 'name'`.
- Admin navigation groups: **Content**, **Shop**, **Sales**, **Stock**, **People**, **Settings**. Each collection sets `admin.group`.
- Role visibility: `admin.hidden` uses the user's roles, so a `stock` user sees only the Stock group (plus their own profile).

### T2 · Business settings and module switches
Files: `modules/settings/globals.ts`, `modules/settings/service.ts`.

- The `BusinessSettings` global with all groups in `04-DATA-MODEL.md` §1. The `loyalty` and `reviews` groups are added by their own milestones, not now.
- `getSettings()` is cached with tag `settings`, revalidated by an `afterChange` hook. It returns the public projection (no IBAN or internal e-mails). `getSettingsPrivate()` is server-only, for documents and e-mails.
- `isModuleOn(name)` is used by the layouts and `admin.hidden`.
- `counters` collection (hidden) + `lib/numbering.ts` `nextNumber(tx, series, year)`, built now because it is a rule of its own (`02-ARCHITECTURE.md` §5.3). Its first caller is `cateringRequests` (`REQ-{YYYY}-{0000}`, `DEM-…` since 9 Nov).

### T3 · Media, pages, legal, globals
Files: `modules/cms/collections.ts`, `modules/cms/globals.ts`, `modules/cms/service.ts`, `payload.config.ts` (S3 plugin).

- `media` with required localized `alt` and the image sizes, stored in S3 (MinIO locally).
- `pages` with blocks (`05-UI-SYSTEM.md` §4), drafts on, live preview off (not needed).
- `legal`; the `Header`, `Footer` and `HappyHour` globals.
- `afterChange` hooks call `revalidateTag` with the doc's tag (`page:<slug>`, `legal`, `header`, `footer`, `happy-hour`). Check the exact `revalidateTag` signature in the Next 16 docs.

### T4 · Public pages from the CMS
Files: `app/(site)/[locale]/{maison,contact,catering,events}/page.tsx`, `events/[slug]/page.tsx`, `legal/[slug]/page.tsx`, `components/site/blocks.tsx`, the home sections (data swap).

- **Home:** the sections keep their layout. Text that the client must edit (hero titles, happy-hour times, contact details, store hours) comes from globals or settings, and the rest stays in dictionaries. The `HappyHour` section reads the `HappyHour` global. `Footer` and `Store` read `BusinessSettings.hours` and `business`, formatted with `lib/time.ts`, and show "open now" from the hours.
- **The House** (`maison`) is a `pages` doc rendered by `Blocks`. The seed reproduces the prototype's `maison.tsx` sections as blocks.
- **Events list** is the `events` collection (published, upcoming), with the prototype card via `MediaCard` (`overlay`) + `MediaGrid` (`hairline`). The Reserve button is not rendered until M2.3.
- **Legal pages** are `legal/[slug]`, with footer links to them.
- `generateMetadata` on each page comes from `seo` fields with a fallback to the title, plus `alternates`.

### T5 · Contact and catering requests
Files: `modules/cms/actions.ts` (`sendContact`), `modules/catering/{collections,actions,service}.ts`, `app/(site)/[locale]/catering/page.tsx`, `app/(site)/[locale]/contact/page.tsx`.

- `sendContact` (`publicAction`): `name`, `email`, `phone?`, `subject`, `message` (10–4000 chars), plus a honeypot field `website` that must be empty. Rate limit 5 per 10 min per IP. It sends a staff e-mail to `MAIL_STAFF_TO` and a confirmation to the sender in their locale. Nothing is stored, because the contact form needs no database.
- `cateringPackages` (seeded from `PACKAGES` in `catering.tsx` + dictionary texts) and `cateringRequests`.
- `requestCatering` (`publicAction`): validates package, guests ≥ package `minGuests`, a date ≥ today + 2 days, time, location, name, phone and email. The estimate is computed **server-side** as `pricePerGuestCents × guests`. It stores the request with a number from `nextNumber('cateringRequest')` and e-mails staff and customer.
- Replace the prototype's `setTimeout` + toast with `ActionForm`. The visual result is unchanged.

### T6 · E-mail
Files: `lib/mail.ts`, `modules/notifications/templates/{layout,contact,catering}.tsx`.

- `lib/mail.ts`: a lazy nodemailer transport; `sendMail()`; `render(Template, props)` with `react-dom/server` `renderToStaticMarkup` + a plain-text version.
- One shared e-mail `layout.tsx` with logo, ink/bone/gold colours, inline styles and the footer with business info. Every later e-mail reuses it.
- E-mail strings live under a `mail.*` namespace in the four dictionaries.
- Sending happens after the response through Next's `after()`, so a slow SMTP server never blocks the user. Check `after` in the Next 16 docs. Failures are logged and never thrown to the user.

### T7 · Cookie consent and seed
Files: `components/site/cookie-consent.tsx`, `scripts/seed.ts`.

- Cookie consent: a small bottom bar (prototype palette) offering "Essential only" or "Accept analytics", stored in a cookie. It exposes a consent-gated script slot that is **empty** (Q§12: no trackers; ready for GA4).
- `seed.ts` is idempotent (upsert by slug). It creates: the first admin (from CLI args), BusinessSettings with LU VAT defaults and the hours from the prototype's `contact.tsx` and `Store.tsx`, the Header and Footer globals, the HappyHour global, the `maison` page, 4 legal stubs **marked draft** (they are published only when DEP-05 texts arrive, so there is no placeholder in public), 3 catering packages, and 4 events. Texts come from the 4 prototype dictionaries.

### T8 · Tests
- Integration: an inactive user's login fails; a `sales` user's `updateGlobal('BusinessSettings')` is forbidden; `requestCatering` stores the server-computed estimate (the client-sent value is ignored); `nextNumber` gives 1, 2, 3 for 3 sequential calls, and parallel calls are covered in M3.2.
- E2E: `tests/e2e/locale.spec.ts` (`06-TESTING.md` §3.3 #1).

## Acceptance criteria

- **AC-M1.3-01 [V-I18N]** Given each public route in each of the 4 locales, when it is rendered, then no string from another locale appears (e2e samples dictionary keys and a localized CMS field).
- **AC-M1.3-02 [V-ADMIN] [R9]** Given an admin edits Saturday's hours in BusinessSettings, when the contact page and footer reload, then the new hours are shown with no redeploy.
- **AC-M1.3-03 [V-CONT]** Given the admin edits The House text in EN, then `/en/maison` shows it and `/fr/maison` is unchanged.
- **AC-M1.3-04 [V-NOTIF] [V-CONT]** Given a catering request for 20 guests of "Mesa Farta", then staff and customer receive e-mails (Mailpit) in the customer's locale, and the stored estimate equals price × 20.
- **AC-M1.3-05 [V-ADMIN]** Given a user with only the `stock` role, then the admin shows only the Stock group, and `BusinessSettings` cannot be opened.
- **AC-M1.3-06 [R9]** Given `modules.attendance` is unchecked, then `isModuleOn('attendance')` is false. The gated routes are added by their own milestones.
- **AC-M1.3-07 [V-DES]** The header is readable on every page at 360, 768 and 1280 px (checklist).
- **AC-M1.3-08 [V-CONT]** The cookie bar appears on first visit, the choice persists, and no third-party script loads in either case.
