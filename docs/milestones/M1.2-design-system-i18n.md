## Goal

The prototype's look running in Next, built from **one** set of shared components: tokens, fonts, `Button`, `Field`, `Container`, `PageHero`, `MediaCard`, `MediaGrid`, `QtyStepper`, `Reveal`, `Nav`, `Footer`, `LanguageSwitcher`, `ActionForm`, all locale-prefixed. After M1.2, `/fr`, `/en`, `/de` and `/pt` render the home page pixel-identical to the prototype. The content still comes from the dictionaries; the CMS arrives in M1.3.

## In scope / out of scope

- **In:** tokens, fonts, shared components, `[locale]` routing, dictionaries, the home page port, metadata and hreflang helper, images.
- **Out:** CMS-driven content (M1.3), the cart's real behaviour (M2.2; the cart UI shell is ported here but is not rendered until M2.2), shop data.

## Tasks

### T1 · Tokens and fonts
Files: `app/globals.css`, `app/layout.tsx`.

- Port `styles.css` per `05-UI-SYSTEM.md` §1. Replace `@source "../src"` with Tailwind 4's default source detection, or point it at `app` and `components`.
- `app/layout.tsx` is the root and has no `<html>` locale logic. Check in the Next 16 docs whether the root layout or `[locale]/layout.tsx` must own `<html lang>`, and follow it so that `lang` equals the active locale.
- `Cormorant_Garamond` (weights 300, 400, 500, italic) and `Inter` come from `next/font/google`, exposed as `--font-serif` and `--font-sans` and mapped in `@theme`.

Verify: an `<h1>` renders in Cormorant and the body in Inter; the colours match the prototype in a side-by-side screenshot.

### T2 · i18n routing and dictionaries
Files: `lib/i18n.ts` (+ test), `dictionaries/{fr,en,de,pt}.json`, `proxy.ts`, `app/(site)/[locale]/layout.tsx`.

- Copy `golden-grape-luxembourg/src/locales/*.json` into `dictionaries/`. All four have the same 400 keys (verified on 2 Nov). The keys that hold catalogue data (`shop.products.*`, `snackPage.menu.*`, `eventsPage.list.*`, `cateringPage.packages.*`) are used only by the seed (M1.3 T7, M2.1 T6) and are **deleted from the dictionaries** once that data lives in Payload.
- `lib/i18n.ts`: `LOCALES = ['fr','en','de','pt'] as const`, `DEFAULT_LOCALE = 'fr'`, `isLocale()`, `getDictionary(locale)` (a dynamic `import()` per locale, server-only; type `Dictionary = typeof fr`), `alternates(pathWithoutLocale)` returning Next `metadata.alternates.languages` + `x-default`, and `localePath(locale, path)`.
- `proxy.ts`: a request without a locale prefix is redirected (307) to `/{best}` + path, where best is the `NEXT_LOCALE` cookie, then `Accept-Language`, then `fr`. The matcher excludes `admin`, `api`, `staff`, `_next`, static files and `favicon.ico`. Confirm the matcher syntax and the redirect API in `16-proxy.md`.
- `[locale]/layout.tsx`: `generateStaticParams` returns the 4 locales; an unknown locale calls `notFound()`; it renders `Nav` and `Footer` and the `Toaster`.
- The prototype's localStorage `gg_lang` detection is **replaced** by the URL. `LanguageSwitcher` sets the `NEXT_LOCALE` cookie and navigates to the same path in the new locale.

Unit test `lib/i18n.test.ts` checks the `06-TESTING.md` §3.1 vectors **plus a key-parity test**: every leaf key in `fr.json` exists in `en`, `de` and `pt`, and none is an empty string. This catches missing translations, which would otherwise ship silently.

### T3 · Primitive components
Files: `components/ui/{button,field,action-form,sheet,dialog,sonner,input,textarea,select,label}.tsx`, `lib/cn.ts`.

- `Button` (cva): implement the variants and sizes in `05-UI-SYSTEM.md` §3.2 by moving the exact prototype class strings into variants. Every pill button in the prototype must be reproducible with `<Button variant size>`, with no extra `className` other than layout (`w-full`, margins).
- `Field`: one component for underline inputs, textarea and select, showing a field error under the input in `text-xs text-red-700`.
- `ActionForm`: `useActionState` wrapper. While pending, the submit button shows the dictionary's sending label and is disabled. On `ok` it shows a `toast.success`; on an error it shows field errors plus a `toast.error` for non-field errors.
- shadcn primitives: copy from the prototype's `src/components/ui/` only the files listed, and adjust imports (`@/lib/utils` → `@/lib/cn`).

### T4 · Site components
Files: `components/site/{container,page-hero,media-card,media-grid,qty-stepper,reveal,nav,footer,language-switcher}.tsx`.

- Port `Nav.tsx`: TanStack `Link` becomes `next/link` with `localePath`; `useLocation` becomes `usePathname`. The home check is `pathname === '/' + locale`. Logos come from `next/image` (`logo-dark.png`, `logo-light.png` copied to `public/brand/`). The nav links come from props, so `Header` global data can be passed in M1.3; until then they come from the dictionary.
- Port `Footer.tsx` with the same data approach.
- `PageShell.tsx` is **not** ported as a component: it is `PageHero` + `Container` inside the locale layout.
- `Reveal`: merge `Reveal.tsx` and `use-reveal.ts`; add `prefers-reduced-motion`.
- The search icon in `Nav` links to `/[locale]/shop?q=` (M2.2). Until M2.2 it is hidden, because no placeholders are allowed.
- The account icon is hidden until M2.2 for the same reason; the cart icon is hidden until M2.2.

### T5 · Home page
Files: `app/(site)/[locale]/page.tsx`, `components/site/home/{hero,universes,craft,story,store,happy-hour,events,social-proof,marquee,hospitality}.tsx`.

- Port each section from `golden-grape-luxembourg/src/components/site/*.tsx` 1:1. A section receives `t` (its dictionary slice) and `locale` as props, with no `useTranslation`. Only sections with interaction or animation are client components.
- Replace each repeated header, button, card or grid pattern with the §3.2 components, and confirm the visual result is unchanged.
- `metadata` comes from `generateMetadata` with title, description, OG and `alternates(path)`; copy the titles and descriptions from the prototype's `head()` for each route.

### T6 · Images (DEP-01)
Files: `public/brand/**`, `lib/brand.ts`.

- `golden-grape-luxembourg/src/lib/brand.ts` maps slots to Lovable CDN URLs (`.asset.json`), which **do not work outside Lovable**. Ask for the originals (DEP-01).
- Until they arrive, use the real files that exist in `golden-grape-luxembourg/src/assets/*.jpg` (hero-wine, store-interior, universe-*, craft-*, happy-hour, gourmet-table) for the matching slots, and record which slots are still missing in `PROGRESS.md`.
- `lib/brand.ts` keeps the same exported slot names (`home`, `owners`, `shop`, `snack`, `catering` + legacy aliases), pointing to `/brand/...` files. From M1.3 on, CMS-managed images replace these slots one page at a time. `lib/brand.ts` is then deleted once it has no imports (target: end of M2.2).
- Every image is rendered with `next/image` and correct `sizes`. The hero uses `priority`.

## Acceptance criteria

- **AC-M1.2-01 [V-I18N]** Given `/`, when it is requested with `Accept-Language: de`, then it redirects to `/de`; with no header, to `/fr`.
- **AC-M1.2-02 [V-I18N]** Given `/pt` and the switcher set to EN, then the URL becomes `/en` with the same path, and every UI string is English (key parity test passes).
- **AC-M1.2-03 [V-DES]** Given the prototype and the port side by side at 1280, 768 and 360 px, then the home page matches: fonts, colours, spacing, header transparency on home and solid on scroll.
- **AC-M1.2-04 [V-SEO]** Given any page, then its HTML has `<html lang>` equal to the locale, a canonical URL, and 4 `hreflang` alternates + `x-default`.
- **AC-M1.2-05 [V-DES]** `grep -rn "rounded-full bg-ink text-bone" app components` returns only `components/ui/button.tsx` (no duplicated pill classes).
- **AC-M1.2-06 [V-DES]** No visible control links to a feature that does not exist yet (search, account and cart are hidden until M2.2).
